# Build sequence, release gates and evolution

## Sequence

M0: reconcile sources and contracts once; preserve and extend the verified core.
M1: real Apple target and single-room end-to-end path: capture -> retained source
    -> normalized graph -> 2D/3D -> reopen local draft. Synthetic UI alone fails.
M2: continuous multi-room capture, topology, recovery and exceptional geometry.
M3: production editing/undo/accessibility and durable local revision/outbox work.
M4: polished graphic 3D, move-through navigation, cutaway and full exports.
M5: validated integration boundary and offline publication UX, still disconnected
    from live OS/Moldo unless separately authorized.
M6: baseline-device performance, physical/user acceptance, security and distribution.

Parallelize independent portions after the relevant contract is fixed; don't
hold UI work until every sensor edge case is solved. Don't declare a milestone
complete if a required user action only manipulates fixture data. See queue IDs
and file ownership rather than inventing a separate task system.

## Release gate

No release-ready claim until: actual Xcode build; real iPhone capture; crash/reopen
and interruption tests; supported topologies; touch and accessibility acceptance;
export fidelity; explicit data/privacy policy; artifact integrity; tested permissions
for any enabled receiver; distribution/signing configuration; documented rollback.
Real-data deployment, TestFlight/App Store distribution and live backend writes
require their actual owner/account authorization. An Apple developer account or
signing identity must never be invented, logged or hard-coded in this package.

## Initial completion is not endless scope

Capture, correction, 2D/3D, saving, export, safety and the specified integration
boundary are v1. Do not add 360, video, furniture, chat, company accounting,
training management or other OS tools to this product. There is no mandatory
AI endpoint, model-training pipeline or subscription screen for the first build.

## After v1

Extensions may add measurement validation, higher-scale captures, collaborative
editing, more native devices, specialized overlays or alternative inputs only
through explicit requirements, adapter contracts and performance evidence.
Keep old saved projects readable. Migrate copies transactionally and retain a
rollback path; never make a migration failure destroy the original artifact.

## Accountable handoff

At each meaningful checkpoint record changed code/contracts; verified evidence;
not-tested behavior; remaining gates; and the next concrete task. Never claim
future autonomous continuation without a running supported process. Background
queues in the product are not background ChatGPT workers.
