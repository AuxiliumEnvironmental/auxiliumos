# Working rules

Source precedence: latest explicit owner instruction; actual reviewed repository
and newer changes; REQUIREMENTS.json + contracts; docs; older chat or speculation.
This package never overrides platform permissions or evidence requirements.

Lead owns shared contracts, BUILD_STATE/QUEUE, integration and release decisions.
Workers own the paths assigned in agents/. Request a contract change rather than
editing another worker's API. No agent may call its own review independent.

Use BUILD_QUEUE.json for implementation order. Update durable state after each
coherent slice, not every small edit. Avoid repeated planning, unbounded research,
full-suite reruns on unchanged inputs and speculative dependency rewrites.

Generated files must retain their source and regeneration commands. Commit source,
lockfiles and migrations when appropriate, not .build, credentials, raw real-world
scans or device signing material. Never include font binaries in distributions.

No 360, arbitrary photo/video reconstruction, photorealism, verified quantities,
competing business directory or automatic OS/Moldo access. Design for extensions
without implementing speculative plugins or an enterprise plugin marketplace.

Contract first, real function next, risk-focused verification, then preserve.
Use "Color" and US English. No em dashes in product copy. Retain exact user
content instead of silently rewriting technical findings.
