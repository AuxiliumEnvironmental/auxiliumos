# Consequential edge cases
Use each case where its affected requirement is implemented; do not manufacture passed evidence for planned behavior.

- C01: another tenant ID; unassigned site; disabled user retaining another role; old session after removal; guessed file key; aggregate leaking an inaccessible child; technical admin attempting professional release.
- C02: draft after approved review; changed checksum; simultaneous releases; stale package child; replacement draft while old report remains current; withdrawn link; hold without access restriction; access restriction without hold; signed URL issuance recorded separately from actual retrieval.
- C03: client message requests free extra work; sampling declined; cap exceeded mid-visit; signature callback replay; changed scope after signature; original terms versus effective authorized amendment; expired/revoked delegation; partial money export.
- C04: failed migration; lost object with database metadata retained; restore from backup; notification/provider outage; interrupted upload; duplicate/background job after restart; credentials rotated; corrupted cache/evidence; incomplete handoff.
- C05: empty, error, no-permission, loading, offline/stale edit, large upload and partial success; phone keyboard and focus; unknown metric mistaken for zero; multiple account switching.
- C06: OS unavailable; Moldo unavailable; reordered events; integration revoked; duplicate external ID; same address across clients; unauthorized audience expansion; export at separation.
- C07: suspected PHI in attachment; malicious prompt in file/email; ungrounded extraction; missing source; model timeout; attempted autonomous report approval.

Select tests by actual changed risk; one well-placed lower-layer test can cover several UI routes. Keep a small browser set proving complete user actions. Record unexpected cases and their requirement/task IDs rather than growing duplicate checklists.
