AuxiliumOS AI Tool Workflow & Realistic Timeline
How to use current AI coding tools without losing control of the product
Prepared for Auxilium Environmental | Working Blueprint | June 14, 2026
Operating rule: AI can accelerate execution, but it must not own business rules, permissions, document release, scope authority, or professional judgment. The system wins only if the durable docs, tickets, tests, and review gates are stronger than the chat.

Use every feature as a ticket, every code change as a branch, every merge as a reviewed PR, and every regression as a test.

2. Golden workflow for AI-assisted development
Update the durable docs first: PROJECT_BRIEF, ROADMAP, DECISION_LOG, GLOSSARY, RULE_REGISTRY, PERMISSIONS_MATRIX, DOCUMENT_CONTROL, TEST_SCENARIOS, AI_HANDOFF.
Create one GitHub Issue per feature. The issue must include purpose, users, objects, states, permissions, audit events, acceptance criteria, tests, and out-of-scope notes.
Start a new AI coding session with the AI_CONTEXT_PACKET plus the single issue. Do not ask the agent to build multiple modules at once.
Require the agent to produce an implementation plan before code. Approve or correct the plan before it edits files.
Let the agent implement on a feature branch. Require tests with the feature, not after the feature.
Run tests locally and in CI. The PR cannot merge if tests fail or if no tests were added for permission-sensitive work.
Review the diff against the ticket. Reject changes that rename objects, bypass permissions, weaken document release, or add hidden business rules.
Merge only after human review. Update decision log and handoff file immediately.
At the end of each chat, generate a handoff summary: decisions, files changed, tests added, risks, unresolved homework, next three tickets.

Part-time work, unresolved homework, weak specs, or permission rework can double these ranges.

4. Minimum useful PA/client portal
Client login and account isolation.
Client project list with status and project summary.
Released document download area with document version and release state.
Project-linked message thread with message classification and routing.
Simple project request form capturing issue, intent, property, affected areas, urgency, payer/signer, and attachments.
Admin intake queue with request status, assignment, missing info, and decision buttons.
Scope summary and limitation record, even if the full smart-prompt engine is not finished.
Audit log for uploads, releases, downloads, messages, role changes, and admin decisions.
Backup/export process and a clear way to remove or disable access.
5. What not to build first
Custom accounting system.
Full enterprise site passport suite.
Vendor scorecard marketplace.
AI-generated technical conclusions to clients.
Automated scope acceptance without Auxilium review.
Healthcare PHI-capable workflow before security, contracts, and platform selection are resolved.
Complex dashboards that do not drive client action or internal decisions.
Multiple apps with separate client/user/document tables.
6. Definition of done for every feature
Gate
Required proof
Business rule
Written in durable docs and feature issue; not buried only in chat.
Object ownership
Feature clearly states which domain owns the data.
Permissions
Allowed and denied roles are listed and tested.
Audit
Important actions create audit events.
Document control
Any file-related feature respects version, release, class, and download audit rules.
Workflow states
Feature cannot create impossible states or skip required approvals.
Professional review
Technical opinions, scope approvals, sampling decisions, and report releases have human gates.
Tests
Unit/integration/e2e tests exist for the normal path and at least one failure/denial path.
Handoff
AI_HANDOFF and DECISION_LOG are updated.
7. New chat start packet
Paste this before asking an AI agent to help with any new coding or architecture task:
Paste-in instruction: You are continuing AuxiliumOS. Use the canonical data spine and guardrails. Do not invent business rules. Ask or mark homework gaps when internal information is missing. Work on one ticket at a time. Preserve permissions, document control, audit events, professional review gates, and state machines. Before coding, produce a plan, tests, and files to change.

9. Security and production readiness warning
Security rule: Before real client use with sensitive documents, complete permission tests, backup/restore test, document release audit, dependency/secret scan, admin MFA, and outside security/code review. A working demo is not a production-safe portal.
10. Source notes for tool selection
Claude Code is documented as an agentic coding tool that can read codebases, edit files, run commands, and integrate with development tools.
OpenAI Codex is presented as a coding agent for planning, building features, refactors, reviews, and releases across development tools.
Cursor documents Agent, Rules, MCP, Skills, CLI, and AI-first IDE workflows.
GitHub Copilot coding agent can be started from issues and can produce pull requests, but still requires review before merge.
OWASP ASVS and NIST SSDF should guide secure development requirements and verification practices.
Supabase/Postgres row-level security or an equivalent backend enforcement layer is important for multi-tenant object-level protection.
Playwright is appropriate for end-to-end testing of web workflows and permissions from the user interface.
