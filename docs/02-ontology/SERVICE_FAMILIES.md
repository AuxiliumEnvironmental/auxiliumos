## Versioned family record

Each record needs a stable ID and version; internal name; proposed client label and plain-language description; linked issues, intents, technical modules, sampling groups and deliverables; trigger relationships; exclusions; reviewer/qualification requirements; ROM variable references; account-type ordering; source and rationale; effective dates; development/activation status; and approval evidence where required. Refer to [RELATIONSHIP_TAXONOMY.md](RELATIONSHIP_TAXONOMY.md) for relationship types.

Initial development default: all recovered entries are available to internal configuration and synthetic scenarios. No entry is made a live client offer merely by importing this catalogue. Qualification and jurisdiction checks, appropriate professional engagement, and commercial configuration determine whether an offering can be activated. Missing professional inputs become explicit configuration decisions while unrelated development proceeds.

Rules and ontology administration remain governed shared configuration for the existing platform modules. Do not add a disconnected service application or a twenty-first product module just to manage this catalogue.

## Dependencies and acceptance

- Account types order suggestions without excluding otherwise available services. Multiple family tags may apply to one reviewed engagement.
- Issue, intent, method, technical work, sampling, deliverable, scope depth and price modifier remain separate concepts.
- Catalogue edits require a scoped configuration capability and audit history. Ordinary requesters cannot publish changes.
- Existing approved scope retains the versions it used; a new catalogue release does not silently rewrite it.
- Synthetic scenarios demonstrate valid family mapping, an unsupported offering routed for review, a missing qualification, a restricted configuration edit, and historical-version preservation.
- The implementation work item identifies its dependencies, affected requirement IDs, migrations if any, and evidence. A filled catalogue is not runtime completion.
