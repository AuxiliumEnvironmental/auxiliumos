# Intake runtime contract

Development contract, 2026-10-08. Requirements M07/M12/C01/C03/C05/C07; ADR-002; REQUEST_STATE_MACHINE.md; issue/intent catalogue 2026-10-08.1. OD-005/008/009 defaults remain provisional, synthetic only. No live authority, professional approval or mobilization is granted.

## Records and authority

`incidents` is optional event context, not a request or project. `project_requests` preserves an immutable original submission, original issue/intent, catalogue version, submitter and server times; current classification, assignment, state and revision are separate. Preserve legacy request UUIDs and a unique legacy link, original rows and document references. Backfill without inventing incidents. Only new request operations write after cutover. No program/MSA is mandatory.

Current active demo profile, account membership, view_account and view_asset are always required. New exact-facility capabilities: `submit_request` and `triage_request`. A submitter can see their own requests; a triager can see requests within exactly granted facilities. Neither role labels nor uploader status imply triage or technical/commercial authority. Assignment requires the assignee's current triage entitlement at the same facility. Account/facility scope is immutable. Deny direct writes, unlinked/anonymous/service impersonation, inactive membership, cross-account links and stale revisions.

## Stable API

Public minimal invoker RPCs delegate to private checked implementations. UUID identifiers; snake_case wire fields. Mutations return `{request_id, revision, status}`. Lists return JSON `{items, next_cursor}`; detail returns an item or null. Exceptions: SQLSTATE 22023 validation, 42501 safe unavailable/forbidden, 40001 stale revision, 23505 changed idempotency payload. No raw SQL messages are shown by the UI.

* `intake_catalogue()` returns `{version, issues:[{id,label}], intents:[{id,label}], statuses:[string]}`. Use all source catalogue labels, without inventing valid scientific combinations.
* `submit_project_request(p_account_id uuid, p_facility_id uuid, p_idempotency_key uuid, p_submission jsonb)` accepts only `{title, original_wording, issue_id, intent_id, urgency, affected_area, site_contact, access_notes, safety_flags, payer_note, signer_note, incident_id?, new_incident?}`. Title 1..160, narrative 1..8000, other text <=2000, urgency routine/urgent/emergency, safety_flags <=20 bounded strings, incident optional. new_incident `{title, occurred_at?}` is mutually exclusive with incident_id and creates a same-facility event atomically. Real names/PHI excluded in development. Original submission is immutable. Submission creates only `submitted`, revision 1; exact retry returns original identity, changed payload conflicts.
* `list_project_requests(p_account_id uuid, p_after_id uuid default null, p_limit integer default 50, p_status text default null)` returns authorized UUID-ordered page, limit 1..100, no unfiltered count.
* `get_project_request(p_request_id uuid)` returns authorized detail or null.
* `list_intake_assignees(p_account_id uuid, p_facility_id uuid)` returns `{profile_id, display_name}` items only to a current exact-facility triager. No directory-wide staff leakage.
* `triage_project_request(p_request_id uuid, p_expected_revision bigint, p_changes jsonb)` accepts only `{assigned_to_profile_id?, status?, classified_issue_id?, classified_intent_id?, next_action?}`. Preserve original submission; audit each assignment/classification/transition without logging narrative. next_action <=2000. Atomic expected-revision check; no implicit authority from a state.
* `respond_project_request(p_request_id uuid, p_expected_revision bigint, p_response text)` appends an immutable submitter response (1..8000), without replacing original wording, only in needs_client_information; moves back to intake_completeness_review.

Detail/list items: `id, account_id, facility_id, incident_id, title, original_wording, original_issue_id, original_intent_id, classified_issue_id, classified_intent_id, catalogue_version, urgency, status, revision, assigned_to_profile_id, next_action, created_at, updated_at, can_triage, can_respond`; detail additionally `original_submission, responses:[{id,body,created_at}]`. Nulls allowed only for optional values; no caller-selected actor/time. Permission booleans are current UI hints, never mutation authority. Legacy originals with no recorded classification keep null issue/intent and catalogue version `legacy-unversioned`; preserve the whole source row and use its title as its only recorded original wording. Never invent an incident or prior classification. Assignee RPC returns an array. Safety-flag strings are 1..200 characters, at most 20.

Initial triage transitions: submitted -> intake_completeness_review; intake_completeness_review -> needs_client_information/classification_review/technical_review/safety_review/declined/cancelled; needs_client_information -> intake_completeness_review/declined/cancelled; classification_review -> technical_review/safety_review/revision_proposed/declined/cancelled; technical_review or safety_review -> needs_client_information/classification_review/revision_proposed/declined/cancelled; revision_proposed -> client_revision_pending/needs_client_information/declined/cancelled; client_revision_pending -> needs_client_information/classification_review/declined/cancelled. Entering a review state requests review, it does not complete it. Needs-information requires assignment and a next action. Agreement approval, ROM approval, scheduling, conversion and expired automatic transitions stay unavailable until their specific authority contracts are implemented. Terminal records cannot be reopened by this API.

Legacy titles retain the original foundation's 250-character read bound; new submissions remain limited to160. The legacy schema recorded no urgency: its structural `routine` value is not a submitted fact, and `legacy-unversioned` rows display urgency as **Not recorded**. The sole post-cutover legacy insertion exception is trusted-owner bootstrap of the exact unchanged canonical synthetic seed, atomically mapped to the new records without fabricating a runtime actor; no application/service legacy writer is exposed.

## Integration allocation

Backend owns its generated intake migration, database/API tests and fixtures; UI owns intake API/page/styles/tests plus existing router and navigation integration. Lead owns this contract, migration order, shared registers and verification configuration. File workflow follows intake migration and must preserve the added grant combinations and audit families. Allowed intake audit object types are `incident` (incident_created), `project_request` (request_created, request_submitted, request_assigned, request_reclassified, request_status_changed), and `request_response` (missing_information_received), with tenant, actor, immutable identifiers and safe bounded state metadata. Preserve all earlier event families. Any needed contract adjustment is reported once to lead and UI before implementation divergence.
