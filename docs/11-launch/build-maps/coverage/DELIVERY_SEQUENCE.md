As the first patterns settle, move one specialist to the request-to-scope workflow (S06/S09), another to real document acceptance (S05), and another to independent directory or commercial work with settled interfaces. The lead changes staffing according to actual bottlenecks. These are staffing examples, not commands to start simultaneous remote mutations.

## What coverage means

The acceptance register retains all 163 exact criteria from all 28 requirement sets. Every criterion has one accountable map and named partners. Each map includes its exact owned criteria. The catalog register carries every original row, not only category totals. Decision touchpoints preserve all 17 existing activation records and their exact gates. The interface register gives each handoff one producer. These checks establish a complete reference allocation; product acceptance still needs real code and evidence.

The original plan can be useful incrementally. A coherent accepted request or document journey may be demonstrated while later full-scope work remains visible. Any real restricted pilot requires explicit allowed actors/data/actions and its applicable existing gates. Neither a demo nor a pilot can relabel unfinished criteria as complete.

## Later improvements

An improvement within existing intent can reduce steps, remove repeated data entry, prevent a known defect, improve measured performance or clarify a confusing action. Capture its source problem, affected outcome, smallest fix, contract impact and acceptance in the existing issue/queue. New capabilities require explicit owner direction or original-source traceability before becoming committed scope. No speculative extras are added to this sequence.
